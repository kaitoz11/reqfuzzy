# Product goal and evidence

Goal: turn reqfuzzy into a scriptable tool for testing stateful API journeys.

The operator workflow is capture → infer/edit dependencies → script authentication and request preparation → replay valid state → morph a selected request → verify its effects → retain a repeatable test and evidence. Reqfuzzy is the implementation home; the archived Python kvar proposal is not a second implementation.

This implementation provides HAR import, conservative inference, authored ordered/controlled flows, scalar/raw variables, actor cookie isolation, final request hooks, response scripts, a CLI, and local signed-flow examples. PR #12 was merged into `feat/req-fuzzer` after user approval.

The integrated journey-test engine adds reusable mutation cases, exact typed checks, same-session verification after rejection, mutation-survival checks, private/redacted evidence, and fingerprinted reconstruction. Tests record actual HTTP traffic from an independent local reference API, import it, distinguish secure/vulnerable/session-invalid outcomes, reconstruct a case, and refuse input drift. Final code review approved the core fixes, and the actual CLI acceptance outcomes are recorded in [stateful reference evidence](acceptance/stateful-reference.md). PR #13 was retargeted and merged into `feat/req-fuzzer` after PR #12, following user approval.

The user delegated independent application selection. The subsequent [Juice Shop acceptance](acceptance/juice-shop.md) imported actual traffic from a pinned local third-party app and reproduced a negative order total using fresh accounts and dynamically bound IDs. The reusable project is `examples/juice-shop`. This closes the immediate need for an independent acceptance target; an operator-provided capture can be added when available.

PR #14 is merged and extends binding and conservative inference to whole URL segments. The Juice Shop example declares its short numeric IDs explicitly, so the dependency graph shows `add → update` and `login → checkout` without URL-changing hooks. Short or ambiguous IDs still require manual authoring.

PR #15 is merged and adds path-segment mutations and UTF-8 URL-encoded form binding, inference, and mutations. All five locations (`json`, `header`, `query`, `path`, `form`) support set/remove/append/prepend. Static target structure is checked before a campaign baseline or CLI comparison, and proof evaluates the actual sent segment/body, including media type and content encoding for forms. Review approved the final encoding fix; race tests, vet, the CLI build, and Go 1.24/stable CI passed. The development branch includes both slices at merge `624d38e`.

Named cookies extend binding and all four mutation actions to a sixth location, integrated in PR #16 at `ab3ffa1` after review and Go 1.24/stable CI. Response-cookie extraction and HAR response-header preservation support explicit and inferred `Set-Cookie` dependencies. Per-request edits filter the selected name from automatic cookies without mutating stored session state, client defaults, or custom transports; server cookie rotations still update the actor's jar. Proof checks observed named-cookie values, and ambiguous/malformed fields stop or remain unresolved. The signed reference example now declares its short session ID as a cookie dependency; short values still remain outside inference thresholds.

`flow map` adds offline visual authoring, integrated in PR #17 at `f1c35a9`: actor lanes, execution order, all six dependency locations, main/verification cross-phase sources, target highlighting, and a step/binding/extraction inspector. Edits validate before export and preserve exact strings through the Go loaders. The browser cannot send requests or write project files. Actual browser checks exercised addition/reordering, cookie extraction drafts, broken campaign references, export/import, hostile labels, and desktop/narrow layouts with zero network requests; Go 1.24/stable CI passed, including the stable browser job.

Script-controlled flow, integrated in PR #18 at `262f566`, adds declared default/allowed routes, bounded visits, accepted status sets, optional/status-gated extraction, and per-visit output freshness. Campaigns assess the last target status, prove every mutated attempt, support last/numbered/all checks, and plan all visits with checked arithmetic. Summaries/evidence retain decisions and ordinals; the editor preserves control settings and draws loops/backward routes. [Recovery acceptance](acceptance/session-recovery.md) proves rotated token/key signing, new nonces, secure rejection, vulnerable balance increase, replay, and hard exhaustion without a false pass. Go 1.24/stable CI, including browser authoring, passed.

Reusable payloads, integrated in PR #19 at `d96b0f7`, extend campaigns with typed lists, literal/JSONL files, exact integer ranges, shared libraries, stable source/index IDs, fresh bound-value/variable templates, ordered encoders, and exact JSON add/multiply. `flow plan` inspects generated cases and budgets offline. Source fingerprints protect reconstruction; lazy per-visit compilation and aggregate limits bound expansion. The signed recovery integration exercises generated arithmetic cases, changed-wordlist refusal, and nonce templates that change across attempts. Map validation also protects payload-only dependencies. Review and Go 1.24/stable CI, including browser checks, passed.

Integration agreement: the user authorized merging these and future reviewed changes with passing CI into `feat/req-fuzzer`. Continue under that standing approval rather than asking for each subsequent integration.

Multipart and binary scripting in [PR #20](https://github.com/kaitoz11/reqfuzzy/pull/20) extend dependencies, binding, mutation, and observed proof to text fields, raw file bytes, full filenames, and part media types. A bounded editor preserves untouched bytes and replaces colliding boundaries before signing. JavaScript exposes binary request/response representations and byte SHA/HMAC. [Upload acceptance](acceptance/multipart.md) records real capture/import, fresh state, signed binary bytes, secure rejection versus unsafe acceptance, downstream checks, and reconstruction. Review corrected a named-field disposition/proof issue and approved the final regressions. Full local race/floor/vet/build and browser checks passed; remote review/CI remains the development integration gate.

The [operator-workflow audit](operator-workflow-audit.md) maps the original requirements to implementation and application evidence. All required outcomes for the initial scriptable stateful testing tool now have evidence: capture/import, inferred and authored visual flows, dynamic scripts, fresh-state request morphing, downstream checks, protected evidence, and reconstruction. Final delivery depends on the reviewed multipart change passing CI and merging into `feat/req-fuzzer`.

Broader application compatibility and full PayInt corpus/DSL parity remain future work. Distributed execution and a complete Postman collection/API implementation are outside this delivery. No operator capture was available; the user delegated application selection and pinned local Juice Shop provides independent third-party acceptance. The development branch is not yet a release on `main`.
