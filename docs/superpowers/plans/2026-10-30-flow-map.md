# Offline flow map implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline. Steps use checkbox syntax for tracking; request a read-only review before integration.

**Goal:** Make authored and inferred stateful journeys inspectable and editable as an offline visual map.

**Architecture:** The CLI exports a private HTML document containing validated flow configuration and safe campaign metadata. A pure JavaScript core derives graph edges, validates edits, and exports definitions; a separate DOM/SVG layer supplies the interactive editor.

**Tech Stack:** Go 1.24, html/template, embedded HTML/JavaScript, existing yaml.v3 and Goja, native browser SVG/DOM.

**Spec:** `docs/superpowers/specs/2026-10-30-flow-map-design.md`.

## Global constraints

- Keep Go 1.24 and current command/output contracts.
- No runtime web dependencies, target requests, hook execution, or browser project writes.
- New private output only, mode 0600, new parent directories 0700.
- Preserve extraction/binding strings and integer status values in exported flows.
- Exclude raw request/response data, hook source, variable values, target URLs, and case/check operands.
- Honor standing approval for reviewed changes with passing CI into `feat/req-fuzzer`.

## Task 1: CLI export boundary

Files: create `internal/cli/flow_map.go`, `flow_map.html`, `flow_map_test.go`; modify `cli.go` and `output.go`.

Interfaces: `runFlowMap(args []string, stdout, stderr io.Writer, jsonMode bool) int`; payload `format_version`, `requests`, `flows` (`key`, `file`, `label`, `definition`), optional `campaign` (`name`, `target`, `checks` references).

- [x] Call `flow map --project PROJECT --out FILE --json` in a test and verify it fails because the command is missing.
- [x] Load the main project and optional campaign/verification through existing loaders. Convert flow structs to lower-case YAML-keyed maps using yaml.v3, and retain only campaign reference metadata.
- [x] Render the payload through html/template; embed owned code with template.JS and let the template JSON-escape payload data.
- [x] Write a new file with `O_CREATE|O_EXCL` and private permissions. Test no overwrite, no network/hook execution, secret-data exclusion, and hostile text escaping.
