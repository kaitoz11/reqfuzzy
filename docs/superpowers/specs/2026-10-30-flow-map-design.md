# Offline visual flow authoring

Extend the approved stateful API tooling with `reqfuzzy flow map --project DIR --out FILE [--test tests.yaml] [--json]`. It creates a new private, self-contained HTML file. Generation is offline and never executes hooks or sends target requests. Existing show/run/compare/test/replay contracts stay compatible; Go 1.24 remains supported and no browser library becomes a runtime dependency.

The map includes the editable flow definition and registered request names, including actor labels, expected statuses, hook names, extraction selectors, bindings, and binding prefixes. It excludes raw requests, response bodies, variable values, target URLs, hook source, and case/assertion operands. Binding prefixes are flow configuration and are retained for accurate export. The output must refuse overwrite and use mode 0600; new parent directories use 0700. User-supplied text must remain data in HTML and DOM rendering; all resources are embedded and network connections are blocked by CSP.

The browser renders execution order separately from data dependencies. Nodes are ordered within actor lanes; labels identify variable and request location. It supports node/edge selection, search, location filtering, zoom, step addition/deletion/reordering, step fields, JSON/cookie extraction, provided-variable declarations, and all six binding locations. Changes update the map and validation immediately. Undo/redo and reset operate in memory.

With `--test`, include the verification flow and the campaign's reference metadata. Cross-phase variable edges must resolve to their actual source; equal step IDs in different phases must remain distinct. The target is highlighted. Campaign configuration is read-only: edits must preserve referenced target/check steps and check variables. Invalid/forward/duplicate variable references, duplicate step IDs, missing request names, invalid statuses/selectors/locations, and broken campaign references disable export. Hook file existence and raw request structure remain checked by the CLI's normal execution preflight.

Export the active flow as `flow.yaml` or the verification filename, using JSON syntax accepted by the strict YAML loader. Preserve strings and selectors exactly; numeric status values remain integers. Applying an export to the project is an explicit operator action. The map cannot execute a journey or write project files from the browser. A portable file is preferable here to introducing a new server and request-execution API.

Validate CLI privacy/escaping/no-overwrite behavior, execute the shared browser graph/editor logic and round-trip exports through Go loaders, and inspect actual browser interactions/screenshots for both an authored reference journey and the independent Juice Shop project. Read-only review and passing Go 1.24/stable CI precede integration under the user's standing approval.
