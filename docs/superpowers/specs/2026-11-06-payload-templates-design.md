# Reusable payloads and runtime templates

Extend existing campaign cases, preserving Go 1.24, explicit target selection, bounded request planning, proof, private evidence, and fingerprinted reconstruction. The PayInt reference supplies concrete needs: lists of typed values, repeatable string processing, current-value substitutions, and numeric add/multiply. Full PayInt syntax/corpus compatibility is not required.

## Definitions

`Spec.payloads` is an ordered list. Each source has a safe namespace `id` (up to 56 characters) and an action, with exactly one of `values` (typed JSON scalars), `file` (`format: lines|jsonl`, default lines), or `range: {from, to, step}` (inclusive exact integers, step defaults to 1). A remove source instead has no values. Alternatively `{id, use: relative/library.yaml}` loads a reusable version-1 definition containing the source fields except id/use. A library's wordlist is relative to that library's directory; references remain inside the project. No recursive library imports or network loading.

Explicit cases run first, then sources in declaration order and values in source order. IDs are `source-000001` using original one-based indices; collisions are errors. `unique: true` skips byte-identical typed scalar values without renumbering subsequent IDs. Expansion is deterministic and capped at 10,000 source entries/total cases, 8 MiB per definition/source file, 64 MiB aggregate value/render definitions, and 16 encoder stages. Rendered/encoded values are capped at 8 MiB and are not retained as duplicated compiled copies. Lines are literal UTF-8 strings, CRLF is normalized per line, terminal line separators do not add a phantom value, internal empty lines remain empty-string payloads. JSONL requires one valid scalar per line, preserving exact numbers. Ranges use big integers and reject zero/wrong-direction steps or oversized expansion before allocation.

Cases/sources may declare `render` with only `{{base}}`, `{{value}}`, and `{{var:name}}`, plus ordered `encode` operations `url`, `base64`, `hex`, `json`. Rendering/encoding yields a string; untransformed values retain their scalar types. Placeholder substitutions are single-pass data operations, never executable expressions. `base` is the selected field after flow bindings on that visit; variables must be declared before the target and be present at runtime. Rendered values are re-evaluated on each visit before final signing. Remove takes no renderer/encoding/value. Arithmetic actions `add` and `multiply` accept exact numeric operands and apply only to existing JSON numbers, using decimal/integer arithmetic without float64. Arithmetic cannot use string rendering/encoding.

## Integration

`campaign.LoadYAMLWithResolver`/`ResolvePayloads` accept an explicit byte resolver. Plain LoadYAML handles inline sources but rejects external references without one. Resolution materializes cases and clears source declarations before normal validation/run/replay. Case origin metadata retains namespace/index without operands. The CLI resolver bounds reads, contains paths/symlinks, and registers every library/wordlist as a logical input fingerprint. Changed bytes refuse reconstruction before target traffic.

`flow plan --project DIR [--test tests.yaml] [--max-requests N] [--json]` resolves and statically checks a campaign offline, reporting IDs/actions/origins and the checked baseline+case request bound without payload values or hook execution. Oversized plans remain inspectable, with a within-budget flag; execution still refuses them. Runtime template variable references also participate in visual campaign-reference validation.

Keep case values/render text out of normal summaries/recipes. Generated cases use the existing mutation-proof and occurrence-aware checks. A replay reconstructs the same generated ID from unchanged inputs with fresh state. Examples exercise a reusable financial set and encoded text/template payloads; actual signed recovery and independent Juice Shop behavior remain acceptance targets. Review and Go/floor/browser CI precede integration under standing approval.
